## 2. 地图 → 战斗的全屏转场

![transition](shots/fx_transition.png)

pixelfx 的 `transitions/*` 是这一轮里**尺寸最合身**的一类：画布固定 320×180，本工程视口 256×144，
**0.8 倍正好铺满**（320×0.8=256、180×0.8=144），不用凑也不用裁。

`Juice.pixel_transition(scene_path)` 做的事：

1. 建一个 `CanvasLayer(layer=150)`，里面先垫一层 `mouse_filter = STOP` 的 `Control` —— 转场期间不该还能拖手牌；
2. 放 `transitions/pixel-dissolve`，`speed_scale = 1.8`（2.2s → 1.22s），**palette 换成 `gold`**
   （原配是 neon 紫，和地牢的暖棕不搭）；
3. 在效果铺满那一刻（`span * 0.44`）`change_scene_to_file`，之后由效果自己把新场景揭开；
4. `_in_transition` 守卫：连点两个房间时第二次直接忽略。

接进 6 个切换点：地图→任意房间、地图→角色页、战斗→地图、营地→地图、事件房→地图、准备页→地图。

### 性能：139ms 的坑

这类全屏特效第一次烘（BAKED）要 **139 ms**（`iris` 91 ms），正好卡在第一次进战斗那一下。
所以主菜单 `_ready` 里先 `prewarm` 一次：

```gdscript
Juice.prewarm(self, ["transitions/pixel-dissolve"], {"palette": "gold"})
```

⚠️ 这里有个容易踩的坑：**烘焙缓存的 key 包含 palette**。预烘时不带 `palette: gold`，
烘的是另一份缓存，真播的时候照样冷启动。`prewarm` 现在接受第三个参数、原样传给 `play_pixel`，
就是为了这个。

实测：预烘之后 `pixel_transition()` 调用本身 **0.31 ms**（冷启动约 139ms）。

## 3. 出牌手感对照：三档震屏

### 方法（为什么不能直接截图）

实时同步下抓一帧要 5–15ms 的显存回读，三次抓帧的间隔就不一样了，三档参数的时间轴对不齐，
对比不成立。所以用 **`--fixed-fps 60`** 跑：每帧固定推进 1/60 秒，三档的时间轴完全一致。

```powershell
godot --fixed-fps 60 --path . -s res://tools/feel_lab.gd
```

`tools/feel_lab.gd`：每档新开一场战斗 → 改 `shake_amount/shake_time` → 打第一张攻击牌 →
连抓 16 帧，每次拼成一条 `strip_<变体>.png`，同时记录**战斗根节点的位移**（震屏就是挪它）。

用位移而不是"像素配准"来量，是因为墙砖是重复纹理，配准会锁到错的偏移上（第一版就是这么翻车的）。

### 结果

| 变体 | 振幅 | 单步时长 | 有位移的帧 | 抖动总时长 |
|---|---|---|---|---|
| `1_current`（现在用的） | 2.0 px | 24 ms | 7 帧 | **112 ms** |
| `2_punchy` | 3.6 px | 18 ms | 5 帧 | **80 ms** |
| `3_soft` | 1.2 px | 36 ms | 10 帧 | **160 ms** |

![compare](shots/feel/compare.png)

（`Shaker` 是 4 步乱跳 + 1 步回位，共 5 段，所以单步 = 时长/5。）

⚠️ **别拿"峰值位移"当结论**：`Shaker` 每步都是 `randf_range(-a, a)`，我跑两遍拿到的峰值是
`2.97 / 4.50 / 2.00` 和 `3.67 / 2.99 / 1.37` —— 同一档能差 1.7px。稳定的是"几帧/多少毫秒"，不是峰值。

动态对比（三档并排，放慢 3 倍）：[`shots/feel/compare.gif`](shots/feel/compare.gif)

### 结论

- 三条曲线的**形状**差异很清楚：`2_punchy` 是 80ms 内一口气崩完 5 帧（脆），`3_soft` 是 160ms 拖 10 帧（晃）。
- 这是**手感偏好**，不是对错，所以我没动默认值，只把参数抽成了 `@export`：

```gdscript
# battle.gd
@export var shake_amount := 2.0
@export var shake_time := 0.12
```

现在可以直接在编辑器里选中 Battle 节点实时改，不用改代码重跑。
想试脆的就填 `3.0 / 0.10`，想试晃的就 `1.2 / 0.18`，`feel_lab` 里那三档就是照着这个改的。
