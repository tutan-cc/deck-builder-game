# 用 Godot AI MCP + pixelfx 优化记录（2026-11-10）

## 用了什么

| 工具 | 干了什么 |
|---|---|
| **Godot AI MCP**（连的是真编辑器，不是 headless） | `session_manage` 看会话、`project_run` 跑、`game_eval` 驱动流程（点按钮 / 直接进房间 / 击杀）、`editor_screenshot` 截图、`logs_read` 读游戏与编辑器日志、`Performance` 量帧率与绘制调用 |
| **pixelfx**（`addons/pixelfx`） | 代码画的像素特效，给"击杀"和"营地回血"两个大时刻用 |

## 先说结论：这轮不是性能问题

战斗场景实测 **60 FPS / 77 draw call / 154 个节点 / 0 个孤儿节点**（`Performance.get_monitor`）。
帧率已经顶在刷新率上限，所以优化点落在**反馈**上，不是渲染。

pixelfx 的效果画布是 320×180 一级的（`impacts/hit-flash` 80×64、`impacts/crit-hit` 216×136），
而本工程视口 256×144、精灵 16px。缩放到 0.5（正好 2:1，最近邻不糊）之后：

- **击杀**这种"大时刻"缩完 45×40，占屏 1/5，站得住；
- **普攻命中**缩到 0.5 只有 40×32 且内容稀疏，放大到 1.0 又比敌人还大。

所以命中反馈保留原来的 `art/fx/hit.png`，只把 pixelfx 用在大时刻。

## 动了什么（文件 → 为什么）

### 1. `global/fx.gd` → `global/juice.gd`（autoload `Fx` → `Juice`）

pixelfx 的 `core/px.gd` 第 20 行是 `const Fx := preload("fx.gd")`。工程的 autoload 也叫 `Fx`，
全局名把脚本内常量抢走了，加载特效库直接报：

```
Parse Error: Could not find type "Instance" under base "res://global/fx.gd".
```

这不是"用错 API"，是**命名空间撞车**，不解决就一个特效都播不出来。改 autoload 名字（12 处调用点 +
`project.godot` 一行），addons 保持原样不动，将来 `git pull` pixelfx 不会冲突。

### 2. `Juice.play_pixel()` / `Juice.prewarm()`

- `play_pixel(parent, effect, pos, opts)`：薄封装。特效挂在**父节点**上，所以震屏时跟着晃、
  怪死了特效也不会跟着消失。
- `prewarm(parent, effects)`：见下面"量到的数"。

### 3. 击杀演出 —— `scenes/enemy/enemy.gd`

原来是"冒一下烟 + `queue_free`"，等于怪凭空不见。现在在死亡位置播 `explosions/cartoon-pow`（0.45 倍），
一个黄色 POW 爆字，风格和 Kenney 那套像素一致。同时加了 `_dying` 标记，避免 `stats_changed`
重复触发时播两次。

![kill](shots/fx_kill_pow.png)

### 4. 营地回血 —— `scenes/campfire/campfire.gd`

回血原本只有一行文字。现在在火堆上播 `holy/heal`（0.7 倍），读起来是"火光往上冒"。

![campfire](shots/fx_campfire_heal.png)

顺带修了一个 UX：**满血时"休息"按钮直接禁用**（此前点下去会显示"恢复了 0 点生命"，白点一次）。

### 5. 飘字居中 —— `global/juice.gd`

`pop_number()` 原来写死 `-3` 偏移，那是按个位数算的，两位数会偏右。改成按
`label.get_minimum_size().x * 0.5` 居中。

## 量到的数

pixelfx 的 BAKED 模式是「第一次播才烘全部帧」，那一帧卡主线程：

| 特效 | 冷启动（首次） | 缓存命中 |
|---|---|---|
| `holy/heal` | **40.0 ms** | 0.18 ms |
| `spawn/poof` | 27.6 ms | — |

40ms ≈ 掉 2.5 帧。所以加了 `Juice.prewarm()`：进战斗、进营地时先空烘一遍（节点不可见、
下一帧就删），把这一下卡顿挪到**场景切换**那一下，而不是第一次击杀时。

```gdscript
# battle.gd::_ready()
Juice.prewarm(self, ["explosions/cartoon-pow"])
```

## 试过但没留下（省得以后再试一遍）

| 特效 | 问题 |
|---|---|
| `impacts/hit-flash` (80×64) | 缩 0.5 后在墙面背景上读成"一条红色竖条"，不像打击 |
| `impacts/crit-hit` (216×136) | 缩 0.5 还有 108×68，占屏 42%，比敌人本身大太多 |
| `impacts/shield-block` (148×104) | 半透明蓝色圆顶整个盖住玩家，遮挡角色 |

结论：pixelfx 适合**全屏级 / 大时刻**的效果；小命中反馈用原生 16px 帧条更合适。
如果一定要用小命中特效，正路是先用 `pfx sheets` 把效果烘成 16px 级别的贴图条，
而不是运行时缩放。

## 怎么回退

- 单个文件：`git checkout -- scenes/enemy/enemy.gd`（注意：仓库里有你之前未提交的改动，
  回退会一起丢，先 `git diff` 看一眼）
- 整个 rename 回退：`global/juice.gd` → `global/fx.gd`，`project.godot` 里 `Juice=` → `Fx=`，
  再把 12 处 `Juice.` 改回 `Fx.`
- 不想要 pixelfx：删 `addons/pixelfx`，再把 `Juice.play_pixel`/`prewarm` 两个函数和它们的 3 处调用删掉

## 还没做但值得做

1. **把 `Fx` → `Juice` 之外的一批 warning 清掉**（`logs_read(source="editor")` 一次能看到 6 条）：
   `battle.gd:293` 的 `scale` 遮蔽 `Node2D.scale`、`sprite_anim.gd:36` 的整数除法、
   `map.gd:172` 多余的 `await`、`card_state.gd:11` 未使用的 signal、`card_tooltip.gd:16` 未使用参数。
   这些不影响运行，但会淹没真错误。
2. **`addons/godot_ai` 和 `addons/pixelfx` 目前是 untracked**，要不要进仓库自己定
   （godot_ai 每台机器都要重新配插件，pixelfx 是纯 GDScript 可以直接提交）。
3. 想要更"重"的战斗演出，可以用 pixelfx 的 `transitions/*`（全屏，320×180 级别）做
   地图→战斗的转场，那个尺寸和视口是匹配的。
