## P2 · 卡牌拖拽：从状态机到叠放交互（25:10）

**视频里**：先演示手牌拖动、卡牌重叠、打出；1:52 新建 `User Interface` 场景改名 `CardUI`；2:05 加 `ColorRect`（说明用途是"各状态的视觉效果，方便调试"）；2:28 加 `Label` 显示状态名；4:13 用颜色试状态；9:00 的那张图给出了本集核心——**状态机图**：

```
base ──左键──> clicked ──移动──> dragging ──松开──> released ──> base
```

11:00 用 `HBoxContainer` 做 `Hand` 手牌区。

**这里做的**

- `CardStateMachine`（Node）：持有 `states` 字典与 `current_state`，只做"谁当前、切过去、把输入转给当前状态"
- 四个状态各自一个脚本，用 `@export var state: State` 标号 0–3
- `CardUI`（Control）只转发 `_gui_input` 给状态机

关键实现（`card_state_machine.gd`）：

```gdscript
func _on_transition_requested(from: CardState, to: CardState.State) -> void:
	# 迟到的请求直接丢掉：避免"已经松手了，延迟的拖动请求又把卡拽走"
	if from != current_state:
		return
	var next: CardState = states.get(to)
	if next:
		transition_to(next)
```

**两个坑（都是真的踩了才改的）**

1. **拖动必须脱离容器**。卡留在 `HBoxContainer` 里，容器每帧把位置改回布局结果，卡"拽不动"。`dragging.enter()` 里 `reparent(ui_layer)`。
2. **`transition_to` 的缩进**。第一版把整段逻辑包进了 `if current_state:`，导致第一次切换（`current_state` 还是 null）什么都不做，卡永远停在未初始化状态。现象是 `current_state_name()` 返回 `?`。

## P3 · 悬停判定与释放逻辑（25:04）

**视频里**：鼠标移到卡上要有反馈；松手时要判断"这张卡算不算打出去"。

**这里做的**

- `base` 态处理 `mouse_entered/exited`，用 tween 把 `scale` 拉到 1.12、`z_index` 提到 5
- `released` 态分两条路：落在出牌区 → `request_play()`；落回别处 → 按 `original_index` 搬回手牌，0.15s 后回 `base`

```gdscript
func _return_home() -> void:
	if card_ui.get_parent() != card_ui.original_parent:
		card_ui.reparent(card_ui.original_parent)
	var last := card_ui.original_parent.get_child_count() - 1
	card_ui.original_parent.move_child(card_ui, mini(card_ui.original_index, last))
```

**与视频不同**：视频用 `Area2D`（`CardDropArea`）做落点检测；这里用 `Control.get_global_rect().has_point()`，省掉物理查询，128×256 的界面够用。

## P4 · 瞄准敌人与弧线指引（20:52）

**视频里**（抽帧 11:26 确认）：`Battle` 的节点树出现 `CardDropArea(Area2D) + CollisionShape2D`、`BattleUI → Hand → CardUI ×3`、`Enemy → Sprite2D`；这一集在给 Sprite2D 指定 `arrow.png`（字幕："更好的办法是展开 texture 旁的下拉菜单，点 load"）。

**这里做的**：`CardTargetSelector`（Node2D + Line2D），每帧重画一条二次贝塞尔：

```gdscript
func build_arc(from: Vector2, to: Vector2) -> PackedVector2Array:
	var delta := to - from
	var normal := Vector2(-delta.y, delta.x).normalized()
	var bulge := minf(delta.length() * 0.22, 16.0)   # 弧度随距离长，但有上限
	var control := (from + to) * 0.5 + normal * bulge
	...
```

## P7 · Stats UI：数值显示与信号绑定（23:46）

**视频里**（抽帧 9:49 确认，`player.gd`）：

```gdscript
@export var stats: CharacterStats : set = set_character_stats
@onready var stats_ui: StatsUI = $StatsUI as StatsUI

func set_character_stats(value: CharacterStats) -> void:
	stats = value.create_instance()
	if not stats.stats_changed.is_connected(update_stats):
		stats.stats_changed.connect(update_stats)
```

**这里做的**：`StatsUI.bind(stats)` 连 `stats_changed`，刷新时只改两个 Label：

```gdscript
func _refresh() -> void:
	health_label.text = str(stats.health)

	block_label.text = str(stats.block)
```

`Player` 与 `Enemy` 各自在 `bind_stats()` 里把 `stats` 交给自己的 `StatsUI`，并额外刷新能量/意图。

## P10 · 卡牌打出与结算系统（21:00）

**视频里**：目标判断 + 效果结算 + 牌堆流转，这是把前面九集串起来的一集。

**这里做的**（`battle.gd`）

```gdscript
func _on_play_requested(card_ui: CardUI, targets: Array) -> void:
	if not player.spend_energy(card_ui.card.cost):
		card_ui.return_home()          # 能量不够：退回手里，不消耗
		return
	card_ui.card.apply(targets)        # 数据层执行效果
	discard_pile.add_card(card_ui.card) # 进弃牌堆
	card_ui.leave_hand()               # UI 消失
```

回合：

```gdscript
func end_turn() -> void:
	for child in hand.get_children():  # 手上剩的全进弃牌堆
		discard_pile.add_card(card_ui.card)
		card_ui.leave_hand()
	for enemy in get_tree().get_nodes_in_group("enemies"):
		enemy.attack(player)           # 敌人反击，格挡先顶
	await get_tree().create_timer(0.4).timeout
	start_player_turn()                # 清格挡、回能量、抽 5 张
```

抽牌堆空了会把弃牌堆洗回去（`_reshuffle()`）——这是 roguelike 卡牌的核心循环。

## P12 · 回合管理与抽牌：依赖注入、PlayerHandler、Tween 延迟抽牌（19:07）

**视频里**：把"牌堆 + 抽牌 + 弃牌 + 回合开始"从 Battle 里拆出去，独立成 `PlayerHandler`；抽牌要一张一张出现，不是瞬间刷 5 张。

**这里做的**

`PlayerHandler`（`scenes/player/player_handler.gd`）持有 `draw_pile` / `discard_pile`，暴露：

```gdscript
func setup(player_node: Player, hand_node: HBoxContainer, layer: CanvasLayer) -> void
func build_deck(cards: Array[Card]) -> void
func start_turn() -> void          # 清格挡 + 回能量 + 抽满
func draw_cards(amount: int) -> void   # 每张之间 await draw_delay
func discard(card_ui: CardUI) -> void
func discard_hand() -> void
func reshuffle() -> void
```

**依赖注入**：`setup()` 把 player / hand / ui_layer 传进去，handler 完全不知道 `Battle` 的存在——换场景（商店、奖励界面）可以直接复用。

抽牌间隔：

```gdscript
func draw_cards(amount: int) -> void:
	for i in amount:
		if draw_pile.is_empty():
			reshuffle()
		var card := draw_pile.draw_card()
		if card == null:
			return
		_spawn(card)                                         # 淡入 + 0.85→1 缩放
		if draw_delay > 0.0:
			await get_tree().create_timer(draw_delay).timeout  # ← 这就是 Tween 延迟抽牌
```

**踩的坑**：新加的 `class_name`（`PlayerHandler` / `CardPileView` / `CardTooltip`）不会自动进全局类缓存，`Battle` 里写 `var handler: PlayerHandler` 会报 `Could not find type`。必须跑一次 `--import` 让 `.godot/global_script_class_cache.cfg` 更新。

## P13 · 结束回合与弃牌：按钮 UI、弃牌动画、洗牌堆、回合重置（19:45）

**视频里**：End Turn 按钮要有可见的禁用状态；弃牌要有飞行动画；抽牌堆空了要把弃牌堆洗回去。

**这里做的**

`end_turn()` 的节奏（`battle.gd`）：

```gdscript
func end_turn() -> void:
	if enemy_turn:
		return
	enemy_turn = true
```

## 第十九轮补充（打不出去的卡：瞄准判定从圆形改成"一列"）

### 现象

伤害牌拖到敌人身上松手，卡直接弹回手里，什么都发生不了。

### 原因

`targets_under_mouse()` 用的是**圆形半径 12px**：

```gdscript
if node.global_position.distance_to(mouse_position()) <= TARGET_RADIUS:
```

但敌人身上玩家真正会瞄的是**头顶的数字**：
- 血量数字在中心上方约 20px
- 意图数字在中心上方约 34px

12px 的圆只盖住精灵本身 → 瞄数字必然落空。而且小屏幕上精灵只有 16px，
容错极小，"明明点到了却打不出去"就是这么来的。

### 改成按列判定

```gdscript
var delta := node.global_position - at
if absf(delta.x) <= 16.0 and delta.y >= -14.0 and delta.y <= 34.0:
```

- 左右 ±16（精灵宽度 + 一点余量）
- 上方 34（够到意图数字）、下方 14（精灵下沿）
- 侧向不放宽，避免误伤旁边那只

实测（同一个敌人，鼠标放不同位置）：

```
中心      -> 命中
血量数字  -> 命中   （原来落空）
意图数字  -> 命中   （原来落空）
斜下 10,10 -> 命中
偏左 15   -> 命中
再往上一截 -> 不命中
```

### 还有两处配套

1. **箭头显示**改成调用同一套判定（`card.targets_under_mouse()`），

```
敌人下方被牌挡住，再往下就是手牌区
```

**卡一拖到敌人身上，就把敌人整个盖住了**，箭头在四周都会被遮。

改成给"卡本身"染色——卡是玩家正在看的东西，不会挡：

```gdscript
card.background.color = base.lerp(Color(0.30, 0.52, 0.34), 0.75) if locked else base
```

锁定目标时卡变绿，松手前一眼就知道"打得到"。世界侧保留敌人放大 1.18×。

### ③ "打不出去"的第二个原因：能量用完没有任何提示

`_on_play_requested` 里能量不够时是静默的：

```gdscript
if not player.spend_energy(card_ui.card.cost):
	card_ui.return_home()   # 什么也不说，卡就弹回去了
```

玩家只会看到"拖出去又弹回来"，以为是 bug。
现在弹一行 **"能量不够"**，并在卡上飘一个红色费用数字。

（顺带确认了能量显示是准的：`CharacterStats.energy` 有 setter 会发 `stats_changed`，
自测里 `energy=3 label=3/4`、`energy=1 label=1/4` 都对得上。）

四个自测场景全绿。
## 第二十一轮补充（能量搬到顶栏 + 把"回合"讲清楚）

### 问题

玩家找不到能量在哪：它贴在角色头顶 (-18,-34)，和血量、护盾挤在同一块，
而且只写 `3/4` 没有标签，很容易被当成血条的一部分。玩家看到"能量不够"的提示
却不知道去哪看、也不知道怎么恢复。

### 改法

能量搬到顶栏，带标签：

```
第 1 层 ◆ 0 能 4/4        抽 4  弃 0  结束
```

- 有能量时黄色 `能 4/4`，用完变暗红 `能 0/4`
- 角色头顶那个标签隐藏（数据还在，`player.energy_label` 仍可用）
- 每次 `stats_changed` 都会刷新（`_refresh_energy_bar`）

### 玩法面板补两条

```
5. 能量用完只能点「结束」，下回合回满
6. 一轮=你出牌 → 敌人行动 → 再轮到你
```

### 顶栏每项的含义（写进文档，也方便以后加 HUD）

| 位置 | 含义 |
|---|---|
| 第 1 层 | 当前层数（地图行） |
| ◆ 0 | 金币 |
| 能 4/4 | 当前能量 / 上限，每回合回满 |
| 抽 4 | 抽牌堆剩余张数（可点开） |
| 弃 0 | 弃牌堆张数（可点开） |
| 结束 | 结束回合，交给敌人行动 |
