## 结论

原来只有 5 个音效（而且 `enemy_block` 定义了却没人播），现在 **11 个**，覆盖打击、格挡、受击、击杀、

全部是阿里云百炼的 `qwen-audio-3.1-tts-next`（"统一音频生成"：人声、音效、环境音）生成的。

## 怎么调的 API

```
POST https://dashscope.aliyuncs.com/api/v1/services/audio/tts/SpeechSynthesizer
Authorization: Bearer $DASHSCOPE_API_KEY
{
  "model": "qwen-audio-3.1-tts-next",
  "input": { "text_prompt": "8-bit 像素游戏音效：…", "format": "wav",
             "sample_rate": 44100, "channels": 1, "seed": 42 }
}
→ { "output": { "audio": { "url": "…（24 小时有效的签名地址）", "duration": n } } }
```

文档给的端点是 `https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/...`（需要业务空间 ID），
但 **`dashscope.aliyuncs.com` 这个通用域名同样能用**，不用配 workspace。

## 一个必须处理的坑：它不会给你"一个短音效"

这个模型是"生成完整声景"的思路，**即使提示词写了"0.3 秒、只有一下"，也会吐 1–30 秒**，
而且同一段里可能反复出现。

所以 `tools/gen_sfx.py` 做了四件事：

1. 生成 → 下载 wav；
2. **找第一个起音点**（4ms 帧的 RMS 包络，超过峰值 −30dB 的第一处，再往前留 15ms）；
3. 截到目标长度，尾部 80ms 淡出，峰值归一到 −1 dBFS；
4. 转成 **ogg vorbis**（Godot 直接吃，11 个文件一共 108 KB）。

## 怎么验的

- **资源层**：`tools/check_sfx.gd`
  ```powershell
  godot --headless --path . -s res://tools/check_sfx.gd
  ```
  逐个 `load()`，校验时长和预期一致 → `SFX_CHECK passed (11/11)`。
- **一致性**：`global/sfx.gd` 的 `SOUNDS` 键与 `art/audio/*.ogg` 一一对应（11=11，无差异）。
- **频谱抽样**（替代"我听不到"）：`slash` 质心 5039 Hz、`block` 3475 Hz——尖锐 vs 闷重，
  和"剑挥砍 / 盾牌撞击"的预期一致，也说明没生成成静音或纯噪声。

## 重新生成 / 换某一个

```powershell
$env:DASHSCOPE_API_KEY = "sk-…"     # 只走环境变量，别写进仓库
$env:FFMPEG = "…\ffmpeg.exe"        # 没在 PATH 里时
python tools/gen_sfx.py slash        # 只重做剑击
python tools/gen_sfx.py              # 全部重做
```

提示词和每条的目标时长都在 `tools/gen_sfx.py` 顶部的 `SOUNDS` 表里，改那里就行。

## 成本与注意

- 计费按输入/输出 token（¥6 / ¥12 每百万）。一次 30 秒的输出约 6000 token ≈ **¥0.07**；
  实际这次每条只生成 1–2 秒，更便宜。11 条总共几分钱。
- 生成的是**签名 URL**，24 小时后失效——所以 `tools/gen_sfx.py` 下完就转存，不依赖它。
- **key 不进仓库**：脚本只读 `DASHSCOPE_API_KEY` 环境变量，`.gitignore` 里也挡了 `sfx_work/`。
