# 音效重做：先试了 AI 生成，最后改用程序化 8-bit（2026-11-11）

> 前面几轮见 [`优化记录-2026-11-10.md`](优化记录-2026-11-10.md)、[`手感与转场-2026-11-10.md`](手感与转场-2026-11-10.md)、
> [`卡牌特效-2026-11-10.md`](卡牌特效-2026-11-10.md)、[`pixelfx-选型-2026-11-10.md`](pixelfx-选型-2026-11-10.md)。

## 结论

音服从 5 个（其中 1 个从没被播过）扩到 **11 个**，覆盖打击、格挡、受击、击杀、出牌、胜负、金币、营地，
并加了**随机音高 ±5%**（连打三张牌不再像机关枪）。

**但最终这 11 个不是 AI 生成的，是程序化合成的方波。** 原因见下。

## 第一轮：AI 生成（能跑，但出来的东西不对）

`qwen-audio-3.1-tts-next` 确实能用：

```
POST https://dashscope.aliyuncs.com/api/v1/services/audio/tts/SpeechSynthesizer
{ "model": "qwen-audio-3.1-tts-next",
  "input": { "text_prompt": "…", "format": "wav", "sample_rate": 44100, "channels": 1, "seed": 42 } }
→ output.audio.url（24 小时有效的签名地址）+ duration
```

两个坑：
1. 文档要求 `https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/…`（需要业务空间 ID），
   但 **`dashscope.aliyuncs.com` 通用域名同样能用**，不用配 workspace。
2. 它是"统一音频生成"（旁白/播客/声景），**一次吐 1–30 秒**，即使提示词写"0.3 秒、只有一下"。
   所以 `tools/gen_sfx.py` 要自己找起音点、截短、归一化、转 ogg。

生成了 11 个之后，用 `qwen3.8-omni-flash` 当"第二双耳朵"去听（`tools/qa_sfx.py`），结果：

| 音效 | omni 听到的 |
|---|---|
| `slash` | 尖锐的气流嘶声后接沉闷的撞击声（勉强） |
| `block` | 低沉的撞击声，伴随短促气流声（勉强） |
| `coin` | **纸牌快速摩擦和洗牌的声音** |
| `damage` | 撞击声 + **男声重复念 "print"** |
| `enemy_attack` | **格斗游戏裁判喊 "Fight"** |
| `enemy_block` | 撞击闷响 + **男声 "Hey"** |
| `enemy_die` | 尖锐音效后接**低沉的男声** |
| `card_play` | 拍手声 + **男子讲西班牙语** + 电子提示音 |
| `victory` | 小提琴高音滑奏（不是号角） |
| `defeat` | 老式游戏机的单音警报 |
| `axe` | 击打声 + **一短促痛呼** |

**11 个里 5 个混进了人声。** 把提示词改成"纯音效，不含任何人声、对话、旁白或语言"再试一次：

```
slash → 唱片刮擦声（或电子故障音效）
coin  → 撕胶带声后接低沉的失败音
damage→ 一声短促的用力喊叫后紧跟沉闷的打击声     ← 还是人声
```

结论：**这个模型不是音效生成器**。它的强项是有叙事/人声的音频内容；让它做短促无人的像素音效，
它会自己"编"出人声和不相干的音色，压提示词也压不住。

## 第二轮：程序化 8-bit（最终采用的）

`tools/gen_chip.py`：纯 numpy 合成方波/三角波/噪声 + 包络 + 扫频，确定性、零成本、不会有人声，
而且这个年代的声音本来就该是方波。

| 键 | 合成方式 | 时长 | 质心 |
|---|---|---|---|
| `slash` | 高通噪声嘶 + 1800→260Hz 方波扫频 | 0.34s | 5591 Hz |
| `block` | 140Hz 闷响 + 760/1140/1520Hz 金属泛音 + 咔哒 | 0.30s | 3032 Hz |
| `enemy_block` | 同上但更低（110/520/690Hz） | 0.30s | 2448 Hz |
| `damage` | 190→70Hz 方波闷响 + 噪声碎屑 | 0.26s | 3140 Hz |
| `enemy_attack` | 90→220Hz 低吼 + 呼风声 | 0.30s | 5183 Hz |
| `enemy_die` | 520→70Hz 下行方波 + 噪声消散 | 0.50s | 3548 Hz |
| `card_play` | 高频噪声"啪"+ 400→1400Hz 快速拉链 | 0.16s | 5665 Hz |
| `coin` | 1568Hz → 2093Hz 两声高频叮 | 0.23s | 3960 Hz |
| `axe` | 噪声劈裂 + 160→85Hz 木响 | 0.32s | 3265 Hz |
| `victory` | C-E-G-C 上行分解 + 尾和弦 | 1.50s | 3535 Hz |
| `defeat` | E-C-A-E 下行 + 低八度 | 1.50s | 2555 Hz |

质心分布也印证了设计意图：**尖锐的（出牌/挥砍/扑击）5000+ Hz，厚重的（格挡/失败）2500 Hz 上下**。

## 接线

| 键 | 触发的时机 |
|---|---|
| `slash` / `block` | 攻击牌 / 防御牌 |
| `card_play` | 出牌（和命中音叠着响） |
| `damage` | **双方** `take_damage` 里（原来完全没有受击音） |
| `enemy_attack` / `enemy_block` | 敌人扑击 / 举盾（后者以前定义了却没人播） |
| `enemy_die` | 敌人死亡 |
| `victory` / `defeat` | 胜 / 负 |
| `coin` | 奖励面板弹出 |
| `axe` | 营地升卡 |

顺带修了个真 bug：`Sfx.play()` 在播放器池为空时直接取 `_players[0]`，会数组越界
（写 headless 自检时踩到的）。现在 `_ensure_players()` 按需建池。

## 追加（同日）：按键音 + 把"出击/加盾"分开

### 1. 全局按键音

没有在每个场景里逐个 `Sfx.play("click")`——那样以后每加一个按钮都得记得接一次。
改成在 `Sfx` 里挂全局钩子：

```gdscript
func _ready() -> void:
	_ensure_players()
	get_tree().node_added.connect(_on_node_added)   # 之后创建的按钮
	_wire_buttons(get_tree().root)                  # 已经存在的按钮

func _on_node_added(node: Node) -> void:
	if node is BaseButton and not node.pressed.is_connected(_on_button_pressed):
		node.pressed.connect(_on_button_pressed)
```

`ui_click` 本身是 0.06 秒两声高音滴答，输出时**单独压 8 dB**（`GAIN = {"ui_click": -8.0}`），
不然在菜单里比战斗音还抢耳朵。

两个例外单独补：
- **地图上的房间**不是 `Button`（是自绘金框的 `Control` + `gui_input`），在 `map.gd` 里手动 `Sfx.play("ui_click")`
- **卡牌**也不是 Button，但它出牌时本来就有 `card_play`，不需要额外点击音

自检里加了这一条（`BUTTON 已自动接上 ui_click`）：新建一个 Button 丢进树里，
验证 `pressed` 确实被接上了——不然这类"全局钩子"最容易悄无声息地失效。

### 2. "出击"和"加盾"太像，重做了两个音

原因是两者都有低频成分：旧的 `slash` 里那个 1800→260Hz 的扫频，落下来正好和 `block` 的
140Hz 闷响在同一频段，听起来都是"闷一下"。

现在按**频段分工**：

| | 质心 | 低频(<500Hz)占比 | 设计 |
|---|---|---|---|
| `slash`（旧） | 5591 Hz | 18% | 噪声嘶 + 下行方波（含低频） |
| **`slash`（新）** | **5608 Hz** | **4.5%** | 双层高通噪声 + 2600→700Hz 窄脉冲方波，**一点低频都不留** |
| `block`（旧） | 3032 Hz | 24% | 闷响 + 金属泛音 |
| **`block`（新）** | **2509 Hz** | **37%** | 220/330/470Hz 不成谐波方波 + 90Hz 胸腔冲击，**无气流** |
| `enemy_block`（新） | 2175 Hz | 42.7% | 比玩家版更低更闷，一听就知道是"对面"在挡 |

现在两者的质心差 2.2 倍、低频占比差 8 倍，是"尖锐的锵"和"沉闷的咚"的区别，不再是同一个音换了个音量。

### 3. 顺手记一个坑

`sfx_work/` 在项目目录里，**Godot 会把里面所有 `.wav` 都当资源导入**（生成了一堆 `.import`，
还把 import 队列拖慢）。加一个 `sfx_work/.gdignore` 让 Godot 整个跳过这个目录。

## 怎么验的

```powershell
godot --headless --path . -s res://tools/check_sfx.gd
```

逐个 `load()` + 校验时长 + 真走一遍 `play()` + 验证 Button 自动接线
→ `SFX_CHECK passed (12/12)`、`BUTTON 已自动接上 ui_click`、6 个播放器装载了音源。

另外，**改了 `.ogg` 之后必须清 `.godot/imported` 再 `--import`**：
headless 的 `--import` 不会因为文件内容变了就重导，`check_sfx` 会读到旧时长（这次就踩了，
第一次跑出来还是旧时长 0.38s/1.60s）。

## 怎么重新生成

```powershell
$env:FFMPEG = "…\ffmpeg.exe"
python tools/gen_chip.py            # 全部
python tools/gen_chip.py coin       # 单个
```

想调某个音色的"手感"，改 `tools/gen_chip.py` 里对应的 `s_xxx()`：频率、扫频范围、衰减曲线都在那。

## 仓库里留下的三个音频脚本

| 脚本 | 用途 |
|---|---|
| `tools/gen_chip.py` | **成品来源**，程序化 8-bit 合成 |
| `tools/gen_sfx.py` | AI 生成（qwen-audio-3.1-tts-next）+ 起音点裁剪。音效不好用，但**做长环境音/旁白可以用** |
| `tools/qa_sfx.py` | 用 `qwen3.8-omni-flash` "听"一段音频并描述，就是它抓出那 5 个人声的 |

## 成本

AI 那条路跑了两轮约 25 次生成，每次 1–2 秒输出（约 300–600 output token），总共**几分钱**。
程序化合成零成本。

## 还没做的

1. **背景音乐**：`art/8_bit_iced_village_lofi.mp3`（14 MB）没被任何代码引用，要么接进去要么删掉。
2. **音量平衡**：11 条都归一到约 −1 dBFS，但菜单/战斗里谁该压谁没细调；要细调得给 `Sfx.play` 加每条的增益表。
3. **`enemy_block` 只有声音没有画面**：敌人格挡时仍然只飘一个数字。
